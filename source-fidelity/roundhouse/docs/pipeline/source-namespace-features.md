# Source-owned namespace features

A source gem can open a class solely to declare children before another feature
supplies that class's methods and state. `rails_multisite`'s connection helpers
have this shape. This is not permission to merge reopenings or choose the first
class record.

The finite file-program lowering proves directly nested simple headers from the
retained source. Every omitted wrapper record must be completely empty, every
wrapper occurrence must have a matching record, and exactly one nonempty owner
must remain. Superclasses, owner mixins, compact/conditional/intervening bodies,
kind changes and real reopening members do not select this projection.

The shared resource IR replaces each wrapper declaration with an ordered
`Opened` binding and retains its child declarations in the same feature. The
prepared emission app removes only the proved empty records. Source-feature
ownership takes precedence over ordinary parent/child declaration-file grouping;
helpers cannot be absorbed into their parent's later main feature. Children keep
their nested lexical headers, not a guessed compact-header constant environment.
A derived require of the already-open parent namespace must not eagerly run its
main body. Other unproved declaration dependencies still refuse. Explicit source
requires, including repeated calls, retain Kernel's cache and effect order.

This remains a bounded profile, selected only by the existing finite graph.
Namespace/ancestor binding writes, callbacks, reflective/dynamic worlds and late
source/IR changes retain refusals. First-class namespace values, namespace
construction, subclass escapes, unproved namespace APIs, main-body upcalls and
autoload namespace lifetimes are not admitted. In particular, an independently
measured native constructor can still reach a later `initialize` too early;
this projection does not disguise that mismatch as supported construction.
The native qualified `respond_to?` prerequisite uses source-point history.

`tests/source_namespace_features.rs` checks original / same lowered CRuby /
native controls with a typed source consumer, early method absence and constant
NameError, late lexical/sibling lookup, real child inclusion and construction,
repeated feature caching, binding/constructor/callback negatives, and late source
or member mutation. No services or observed application values are involved.

This is not core-provider or page acceptance. The unchanged expanded core input
still refuses, including the real singleton-delegated `current_db` API. That
macro's callable closure must be lowered and verified, not declared available by
loosening this namespace proof. Existing frozen-literal and global typing
failures are separate and remain failures.
