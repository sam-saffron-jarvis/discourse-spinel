# Discourse on Spinel — bottom-up `/latest`

Goal: actual Discourse topic list in a browser, then a topic page. This independent
local extraction is **not** the parked whole-app/33MB generated tree or a toy blog.
Reference pin: `../discourse` at `96ce8d44401a8a568ecc71561c26dca8ec6bfeb8`.

## Current checkpoint

The Spinel-produced native ELF serves live anonymous `/latest.json` and a real
Discourse Ember `/latest` document. Actual `.topic-list` rows and `a.title` links
match all 20 current PG-backed API topics on desktop and phone, at direct root and
at `/node/jarvis/widgets/discourse-spinel-app`. Browser evidence is generated by
`make browser-smoke`, not inferred from preload presence.

**Topic content is not implemented.** Correct `/t/<slug>/<id>` links are M2, not
M3. Full plugin/theme/authentication support is not claimed. See `GAPS.md` and
`PLUGIN_SUPPORT.json` for exact scope and deliberate divergences.

## Build and verify

From the run root, always load the task toolchain/service environment first:

```sh
source harness/env.sh
make -C minimal build
make -C minimal smoke
make -C minimal browser-smoke
```

- `build`: stages actual browser assets, then compiles `build/bin/discourse` with
  installed Spinel. It writes load graph, wall time, peak **single-child** RSS and
  ELF/input sizes to `build/compile.json`. No whole-app compiler input or compiler
  optimization is involved. Build outputs and evidence are ignored under `build/`.
- `smoke`: native query/serializer/settings/security tests; fresh synchronous
  read-only Rails oracle comparisons; then its **own** temporary native3498.
  Complete latest JSON equality on two pages is preserved. It checks honest HTML,
  live `topic_list` preloads, real module scripts, escaping/static MIME/traversal
  boundaries and read-only polling. Trap kills/waits the child. No DB fixture/DDL
  or seed writes, no Rails HTTP server, no shared listener reuse.
- `browser-smoke`: its **own** native3498 plus real headless Chromium. Tests desktop
  1440×1000 and phone390×844 with the configured widget prefix and direct root.
  Compares actual Ember topic IDs/titles/links to the native live API; emoji title
  text is reconstructed from real rendered image alt names using source Unicode
  metadata, and title images must load. Captures module/network/console/page errors,
  screenshots, rendered DOM and reports under `build/browser/`. Remote requests
  are blocked and fail the test. All owned native/browser children are cleaned up.

Browser tooling is local Python Playwright plus `/usr/bin/chromium`. The native
runtime itself never invokes Ruby, Rails, Python, Node, an HTTP proxy or subprocess
for serving documents, data or assets.

### Asset inputs

Existing real production core Ember/Rolldown modules are reused from
`build/assets/discourse/`; they are not modified to bypass bootstrap or rebuilt on
every native build. If absent, explicitly reproduce them once:

```sh
source harness/env.sh
minimal/frontend/build-ember-assets.sh
```

`frontend/stage-assets.py` stages actual core CSS/English locale/SVG/icon/browser
scripts/emoji/public images/core worker under `build/assets/native/`. The stage
manifest records original inputs, hashes and deliberate limitations. Build-only
Rails asset compilation, if used for palette/fonts, is synchronous, task-scoped
and read-only; it does not serve responses or create captured preloads. Core common
CSS currently reuses a byte-hashed reference stylesheet-cache artifact. See
`frontend/INTEGRATION.md` for exact reproduction/provenance and remaining locale,
plugin/theme and asset-build gaps. No pinned Discourse sources are edited.

`tools/stage-media.py` copies actual current public avatar image bytes with SELECTs
only into **private** `build/media/`. Native requests still check live username,
current upload membership and secure flags before reading a canonical contained
path. Originals may be served when optimized sizes are absent; external letter
avatars intentionally use the real stock blank fallback because external HTTP is
forbidden. Neither broad uploads nor private build evidence is statically exposed.

## Source and data contract

- `SOURCE_MANIFEST.json` records source paths/SHA-256/revision, selected definitions,
  adaptations and dependency notices. `test/source_contract.py` checks original
  source/vendor hashes and regenerability of the source-only client catalog.
- Source YAML generates the 390-field client-safe core settings catalog; runtime
  reads typed live overrides using bound SELECTs. No raw settings dump, secrets or
  captured Rails preload is served. All emitted fields match the read-only oracle
  on this DB; 375 additional plugin/computed/themeable client fields remain omitted.
- Native Site metadata uses live public categories plus source enums/menu/permission
  projection. Every emitted field is compared to actual Rails getters. The full
  `Site.json_for` oracle attempts a wizard setting INSERT and is correctly blocked
  by read-only PG; its stack remains in the report. Field-by-field comparison does
  not stub that write or claim full serializer parity.
- Common preloads include live native topics, public banner and actual read-only
  mode keys from task Valkey DB0/logical site `default`. Theme/plugin HTML/overrides
  and per-user upcoming-change hooks remain explicit gaps.
- MessageBus5 short polling uses actual live backlog IDs/messages and source
  user/group/client ACL filtering, verified against actual Ruby MessageBus at four
  positions. No canned empty polling body, publish, listeners or long-poll daemon.
- PG is task-only `127.0.0.1:5499/discourse_development`; Valkey `127.0.0.1:6399/0`.
  PG session default-read-only plus explicit per-request read-only transactions.
  No DDL/reset/seed/mutation APIs. Unknown query options fail; cookies do not log in.

## Coordinator launch / existing widget handoff

The worker does **not** restart live3499, touch `run/app.pid`, edit/register widgets
or leave a listener running. After acceptance, the coordinator can restart the
existing task app manager using this foreground command (cwd must be `minimal/`):

```sh
source harness/env.sh
cd minimal
DATABASE_URL="$DSPINEL_PG_URL/discourse_development" \
REDIS_URL='redis://127.0.0.1:6399/0' PORT=3499 \
MINIMAL_BASE_URI='/node/jarvis/widgets/discourse-spinel-app' \
MINIMAL_ORIGIN='https://hub.samsaffron.com' ./build/bin/discourse
```

For a direct local root, omit `MINIMAL_BASE_URI`/`MINIMAL_ORIGIN`. The origin defaults
to the direct loopback listener. `MINIMAL_BASE_URI` must be empty or normalized ASCII
path segments, without trailing slash/query/hash/traversal. Document/asset/import
paths, setup base URI, pagination and links honor it. The current existing widget
forwards `self.path` unchanged after the outer proxy strips the widget mount; native
routing therefore accepts both stripped and full-prefix requests. Proxy Host is
rewritten to localhost, so set trusted `MINIMAL_ORIGIN` for canonical absolute URLs;
arbitrary incoming Host headers are not reflected into the document.
